Running the full eval suite costs time and money, so you don't want it firing on every pull request — most PRs (a README fix, a UI tweak) can't possibly break the twin's behavior. GitHub Actions can look at which files a PR changes before deciding to run. So the workflow says: only bother running the gate if the changed files are ones that affect how the AI behaves — the prompt text files, the model name/settings constants, the twin's skill definitions. Change prompt.py → gate runs. Change README.md → gate stays quiet. It's just a file-path filter list, and each product repo tunes that list to where its own "AI-behavior" files live.
