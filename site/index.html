Replace guess and hope with measure and know.

Evalyn is the evaluation agent for LLM-powered products. It drives your product black-box over its real chat API, grades every reply through a three-tier trust ladder, and returns a CI-grade PASS/FAIL diffed against a committed baseline. Your product stays a black box; the definition of “good” stays yours.

Why
Most teams shipping AI features are flying blind.
Ordinary tests don’t apply: the model answers differently every time, it can be subtly wrong, it can be talked into misbehaving, and “good vs. bad” is often a judgment call. So teams change a prompt, swap a model, feel that something got worse, and wait for users to complain.

  

    
The AI gives different wording every time.
One sample proves nothing. Evalyn runs every probe as repeated trials and reports pass@k and pass^k: the same probe, several times, before it says anything.

    
“Usually safe” is not safe.
Averages hide the danger. Safety-critical probes gate on pass^k: every trial must pass, or the build is red. A lone flip elsewhere is quarantined, not a red build.

    
Never trust a judge you haven’t measured.
An LLM grading an LLM is only evidence once it’s calibrated against human labels. The judge is held to the same standard as the product it judges.

    
It shipped with zero evaluations.
Evalyn’s origin: a real product whose whole value was its AI behaviour, and no way to know when that behaviour drifted. That gap is what this tool closes.

  






  
Three modes
Three questions, three commands, three kinds of answer.
Each mode answers one question and refuses to pretend it answers the others.

  

    

      
evalyn gatesmoke alarm

      
Did I break anything?

      
A fixed probe suite on every change. Deterministic verdicts per probe, diffed against the baseline you committed. Runs in CI and posts one sticky PR comment, updated in place.

      
Output
Run artifact + report; per-probe pass@k / pass^k
Exit
0 pass 1 regressed 2 eval couldn’t run

    

    

      
evalyn compareblind taste test

      
Which version is actually better?

      
Pairwise judging of two gate runs, replayed from captured transcripts, so it never touches your product again. Hard metrics (latency p95, invariant failures) sit beside the verdicts. Advisory by design: no combined “winner” is invented.

      
Output
Markdown report, pair by pair
Exit
0 report 2 couldn’t run — never 1

    

    

      
evalyn discoverthe clever tester

      
What problems don’t I know about yet?

      
A goal-directed adversarial agent works an objective × strategy grid (injection bypass, PII leak, persona break, hallucination) under step, turn and USD budgets. Confirmed findings become minimal repro probes, staged for you to adopt.

      
Output
Inert probes in <pack>/discoveries/
Gate?
Never blocks CI. Discover proposes; the scoring layer disposes.

    

  






  
How it works
A pack in, an exit code out. Everything in between is measured.
The engine knows nothing about your product. Endpoints, probes, rubrics, budgets and the URL allowlist live in a swappable YAML target pack: a universal remote, and you load the profile for your TV.

  


  

    
The trust ladder: three scorers, cheapest first

    

      
1
Invariants free · exact
Deterministic checks: leak patterns, empty replies, must / must-not contain. Failures here are facts, not opinions. The only tier a safety verdict may rest on; it short-circuits before a single judge token is spent.

      
2
Classifier
A cheap LLM judge at temperature 0 with forced JSON. It must quote the verbatim evidence span; otherwise the verdict is scored unsure and never trusted.

      
3
Rubric judge
A strong model, G-Eval style: pinned rubric, frozen human-reviewed grading steps, scores 1–5, k=3 self-consistency with median voting. Judge ≠ generator family, enforced in config.

    

    
≥ 85%
agreement with human-labelled anchors, per rubric, or the judge refuses to run. Override it and every artifact is stamped UNTRUSTED. That number is what the cockpit’s Judge Trust page shows.

Rules the engine won’t bend

    

      
pass^k, not pass@k
Safety probes must pass every trial. “Usually” doesn’t count.

      
judge ≠ generator
Judge and product model families must differ, so there is no self-preference bias.

      
allowlist-fenced
A run refuses any base URL not in the pack. Prod needs --i-know-this-is-prod.

      
hard USD cap
Per-run ceiling, --dry-run estimates, and grading-step caching.

      
errored ≠ failed
A 500 marks the probe INCOMPLETE. It stays in the denominator, never vanishes.

      
runs/ is the database
Append-only artifacts. The cockpit is a pure view; nothing it does is magic.

    

  






  
The cockpit
Seven pages. One of them spends money.
evalyn ui serves a local, loopback-only cockpit over your runs/ directory. Its front door is the history, not a dashboard, and every number is derived from artifacts, never hard-coded.

Get started
Two terminals, one exit code.
The repo ships a toy target so you can watch a gate run end-to-end before pointing Evalyn at your own product.

  

    

      
Local, in two minutes

      
shell
# clone + install (uv)
git clone https://github.com/DashankaNadeeshanDeSilva/evalyn && cd evalyn
uv sync

# terminal 1 — the bundled reference product
uv run python examples/toy_target.py

# terminal 2 — point Evalyn at it and run the gate
export EVALYN_TARGET_URL=http://127.0.0.1:8899
uv run evalyn validate-pack packs/example
uv run evalyn gate --target packs/example

# then open the cockpit
uv sync --extra ui && uv run evalyn ui   # 127.0.0.1:8765

      
NoteOnly gate, compare and discover spend judge tokens — and never beyond the pack’s max_usd_per_run.

    

    

      
In CI, as one reusable job

      
.github/workflows/eval.yml
jobs:
  evalyn:
    uses: DashankaNadeeshanDeSilva/evalyn/.github/workflows/evalyn-gate.yml@main
    with:
      pack-path: packs/yourproduct
      baseline-path: packs/yourproduct/baseline.json
      target-command: "uv run python app.py"
      target-health-url: http://127.0.0.1:8899/health
    secrets:
      EVALYN_JUDGE_API_KEY: ${{ secrets.JUDGE_KEY }}

      
Posts one sticky PR comment, updated in place. Exit 1 blocks the merge; exit 2 tells you the eval itself couldn’t run: a different problem, never conflated.
